# Mail server and DNS prerequisites

Veda Mail reads and writes mail through a provider adapter. It does not replace
your SMTP server, mailbox directory, spam filtering, DNS, or message storage.

## Stalwart JMAP requirements

For the included adapter:

- Stalwart is already installed and healthy.
- Each member has a real mailbox account and password.
- Every allowed email domain exists in Stalwart.
- JMAP is available on a public HTTPS URL.
- Its TLS certificate matches the hostname.
- Veda Mail can resolve and reach that hostname over TCP `443`.
- Browser users do not need direct access to Stalwart from the Veda Mail page.

Use a dedicated hostname:

```text
webmail.example.com  -> Veda Mail
mail.example.com     -> Stalwart HTTPS/JMAP and mail protocols
```

Do not enter Stalwart administrator credentials into Veda Mail. Members
authenticate with their own full email address and mailbox password.

## Domains and member access

The setup/admin allowed-domain list is an application login boundary. If it
contains:

```text
example.com
example.org
```

then `person@example.com` and `person@example.org` may authenticate, provided
those accounts exist at the configured provider. A domain in this list does
not create the domain or any mailbox.

## DNS checklist

DNS is managed for the mail server independently from Veda Mail. A typical
mail domain needs:

- An `A`/`AAAA` record for the mail-server hostname
- `MX` records pointing the mail domain to that hostname
- One valid SPF TXT policy
- DKIM public-key records generated by the mail server
- A DMARC policy and report address
- Reverse DNS/PTR matching the outbound SMTP hostname
- Optional MTA-STS and TLS reporting records
- Optional SRV/autoconfiguration records

Follow Stalwart's current documentation for exact record values. Never copy
another organization's SPF, DKIM, or verification tokens.

Keep mail hostnames in DNS-only mode when using a DNS provider that cannot
proxy SMTP/IMAP. Standard CDN HTTP proxying does not proxy ports 25, 465, 587,
993, or 4190.

## Mail-server firewall

These are common Stalwart ports; expose only the protocols you use:

| Purpose | Protocol | Port |
| --- | --- | --- |
| SMTP server-to-server | TCP | 25 |
| Submission over implicit TLS | TCP | 465 |
| Submission with STARTTLS | TCP | 587 |
| IMAP over TLS | TCP | 993 |
| ManageSieve | TCP | 4190 |
| HTTPS/JMAP | TCP | 443 |

Veda Mail itself needs only outbound HTTPS/JMAP and its inbound web port behind
the reverse proxy.

## Deliverability checks

Before inviting users:

1. Confirm forward DNS and PTR agree.
2. Send to an external mailbox and inspect SPF, DKIM, and DMARC results.
3. Reply from the external mailbox.
4. Confirm SMTP is not an open relay.
5. Confirm port 25 is allowed outbound by the hosting provider.
6. Monitor mail queues, bounces, blocklists, and DMARC reports.

DNS propagation may take time. Do not weaken DMARC or SPF merely to hide an
unrelated provider or firewall problem.

## Adding another provider

The member login remains email/password while a provider module translates
those credentials into the provider's server-side connection. See
[adding a provider](ADDING-A-PROVIDER.md) for the contract and security rules.
